Confirmed causes

  1. A heavyweight coding session per still. Forty-eight successful stills required 790 model requests (median 16, range 9–27), all at high effort. Median input context grew from 20,634 to 50,202 tokens. Stills account for 70.3% of recorded token traffic, not necessarily 70.3% of charges.
  2. Preventable repair loops. Forty-six of 48 stills had failed checks. Across 128 trial calls, 69 failed; reported problems included 264 contrast violations, six occlusion problems and three overlaps. One frame needed four trials and 12 Edit calls, taking 27 requests and 1.37 million total tokens. It repeatedly adjusted contrast from 4.43/4.44 to the required 4.5. Keep validation; supply valid foreground/background pairs and deterministic contrast calculations first.
  3. Large repeated setup. Median frame/design/role/dispatch packet size was 41.4 KB. An inspected session exposed about 81 KB of tool definitions and a 9.6 KB system prompt, including unrelated cron, swarm, web, and goal tools. Its design packet mixed a Blue Professional base with a brand override. Fresh sessions reread instructions for each frame. Cached reuse works (about 94% of recorded input tokens), but does not remove repeated requests or output.
  4. Limits do not cap cumulative spend. Pose allows high effort, 40 tool calls and 32,000 output tokens per response. The six-attempt counter applies to submit, while trial calls are separately constrained only by general time/tool limits. These are not a per-frame or per-series token budget. Usage is read after the Kimi run ends.
  5. Extra orchestration work. The source notebook also incurred 26 revise-story runs, 13 revise-page runs and five storyboard runs. Those include iterative research/organization/review work; this audit does not classify every revision as waste. The old dispatcher attempted 40 quota-failed frame runs. The prior stop-on-shared-failure fix addresses that cascade, but is not the main explanation for the tokens already consumed.

Recommended order

  1. Resolve a compact, contrast-safe theme once and seed deterministic frame scaffolding.
  2. Give still workers only required tools and a consolidated minimal packet; avoid broad agent capabilities.
  3. Use lower effort for first-pass still layout and bounded repair, escalating only complex diagrams. Benchmark quality before adopting globally.
  4. Add live cumulative token limits for each frame, episode and series; stop further dispatch at budget boundaries.
  5. Debounce automatic organization and use incremental updates for related note additions; measure before changing the reactive experience.
  6. Display uncached input, cached input and output separately. Do not present their unweighted sum as quota or price.

No savings percentage is claimed without a controlled comparison. No generation code was changed or paid retry launched during this investigation. Kimi membership shares quota across features, and billing depends on input/output volume and cache hit rate: official membership documentation. Account-wide usage and the exact quota debit cannot be reconstructed solely from these local logs.
